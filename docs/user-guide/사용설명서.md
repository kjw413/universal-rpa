# Universal RPA Studio 사용설명서

Universal RPA Studio는 Windows에서 사람이 하던 반복 업무를 **한 번 시연해서 기록하고,
그대로 다시 실행**하는 프로그램입니다. 프로그래밍 지식은 필요하지 않습니다.

이 설명서는 두 부분으로 나뉩니다.

| 부 | 누가 읽나 | 내용 |
|---|---|---|
| **0부** | 프로그램을 만들어 배포하는 담당자 **1명** | 소스에서 실행 파일을 만들고 나눠주는 방법 |
| **1부** | 실제로 업무를 자동화할 **모든 사용자** | 설치부터 실행·결과 확인·문제 해결까지 |

프로그램(`.exe`)을 이미 받으셨다면 **1부 1장부터** 보시면 됩니다.

# 0부. 프로그램 만들기와 나눠주기

## 0.1 이 작업은 누가 하나요

0부는 **조직에서 한 사람**이, **한 번만** 하는 작업입니다. 만들어진 결과물(폴더 하나)을
복사해서 나눠주면 나머지 사용자는 0부를 볼 필요가 없습니다.

컴퓨터에 프로그램을 설치하고 명령 창에 문장을 붙여넣을 수 있으면 충분합니다.
아래 명령은 **그대로 복사해서 붙여넣으면 됩니다**.

## 0.2 준비물

| 항목 | 조건 |
|---|---|
| 운영체제 | Windows 10 x64 또는 Windows 11 x64 |
| 로그인 상태 | 화면이 잠기지 않은, 직접 로그인한 상태 |
| Python | **3.12 또는 3.13**. 3.14 이상은 안 됩니다 (지우지 말고 3.13을 추가 설치) |
| 인터넷 | 필요 (부품을 내려받습니다) |
| 소스 폴더 | 이 설명서가 들어 있는 프로젝트 폴더 전체 |
| 디스크 여유 공간 | 약 5GB |
| 시간 | 처음 빌드는 **20~40분** 정도 걸립니다 |

> **알아두기**: 빌드하는 컴퓨터에 백신 프로그램의 실시간 검사가 켜져 있으면 시간이 크게
> 늘어날 수 있습니다. 가능하면 작업 폴더를 검사 예외로 등록하세요.

## 0.3 Python 준비하기

### 0.3.1 어떤 버전이 설치되어 있는지 확인

1. 키보드에서 `Windows 키`를 누르고 `powershell`을 입력한 뒤 **Windows PowerShell**을 엽니다.
2. 아래를 붙여넣고 `Enter`를 누릅니다.

```powershell
py list
```

`py list`에서 오류가 나면 아래를 대신 실행하세요.

```powershell
py -0p
python --version
```

**3.12 또는 3.13이 목록에 있으면** 0.4로 넘어가세요.

> ⚠️ **3.14 이상은 사용할 수 없습니다.** 이 프로그램은 `>=3.12,<3.14`를 요구하며,
> 3.14로 설치를 시도하면 `requires-python` 오류로 거부됩니다.

### 0.3.2 3.13 설치하기

> **이미 있는 Python을 지우지 마세요.** 여러 버전이 함께 있어도 문제가 없습니다.
> 3.14가 설치되어 있어도 그대로 두고 3.13을 **추가로** 설치하면 됩니다. 빌드는
> `.venv` 폴더 안의 인터프리터만 사용하므로 시스템 기본 버전은 영향을 주지 않습니다.
> 오히려 3.14를 지우면 그것을 쓰던 다른 프로그램이 깨질 수 있습니다.

방법은 셋 중 하나입니다. 위에서부터 시도하세요.

**① Python 설치 관리자 (가장 간단, 권장)**

`py list`가 정상 동작했다면 이 방법을 쓸 수 있습니다.

```powershell
py install 3.13
```

설치 후 `py list`를 다시 실행해 `3.13`이 보이는지 확인합니다.

**② winget**

```powershell
winget install Python.Python.3.13
```

**③ 직접 내려받기**

[python.org/downloads](https://www.python.org/downloads/)에서 **3.13** 또는 **3.12**의
Windows 64-bit 설치 파일을 내려받아 실행합니다.
설치 화면 맨 아래 **Add python.exe to PATH** 체크박스를 반드시 켜세요.

## 0.4 작업 환경 만들기

PowerShell에서 소스 폴더로 이동한 뒤(아래 `E:\universal-rpa`를 실제 폴더 경로로 바꾸세요)
차례로 실행합니다.

```powershell
cd E:\universal-rpa
Remove-Item -Recurse -Force .venv -ErrorAction SilentlyContinue
py -V:3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev,build]"
```

> ⚠️ **`py -V:3.13` 부분이 핵심입니다.** 그냥 `python -m venv .venv`로 만들면 시스템
> 기본 버전(예: 3.14)이 잡혀 다음 줄에서 `requires-python` 오류가 납니다.
> 3.12를 설치했다면 `py -V:3.12`로 바꾸세요.
>
> `py` 명령이 없는 환경이라면 설치된 실행 파일 경로를 직접 지정합니다.
> 예: `& "$env:LOCALAPPDATA\Programs\Python\Python313\python.exe" -m venv .venv`

첫 줄의 `Remove-Item`은 예전에 잘못된 버전으로 만든 `.venv`를 지웁니다.
처음이라면 아무 일도 일어나지 않습니다.

마지막 줄은 몇 분 걸립니다. 화면에 여러 줄이 흐르다가 `Successfully installed ...`로
끝나면 성공입니다.

### 0.4.1 제대로 만들어졌는지 확인

```powershell
.\.venv\Scripts\python.exe --version
```

`Python 3.13.x` 또는 `Python 3.12.x`가 나와야 합니다. 3.14가 나오면 위 명령을
`py -V:3.13`으로 다시 수행하세요.

이 작업은 `.venv`라는 전용 폴더를 만들어 **이 프로그램에 필요한 부품만** 그 안에 설치합니다.
컴퓨터의 다른 Python 환경은 건드리지 않습니다.

`-e ".[dev,build]"`는 세 묶음을 한 번에 설치합니다.

| 묶음 | 내용 |
|---|---|
| 기본 | PySide6 6.11.1, pydantic, pynput, pywinauto, pywin32, comtypes, openpyxl |
| `dev` | pytest, pytest-qt, mypy, ruff (검사에 필요) |
| `build` | Nuitka 4.1.3 (실행 파일 생성에 필요) |

> 버전이 고정되어 있는 것은 의도된 것입니다. 검증된 조합에서만 빌드를 서명·배포합니다.
> `pip install --upgrade`로 개별 부품을 올리지 마세요.

### 0.4.2 빌드 전에 한 번 확인 (선택)

빌드는 검사부터 수행하므로 생략해도 되지만, 환경이 제대로 잡혔는지 빨리 보고 싶다면
아래를 실행합니다.

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest tests -m "not windows_e2e and not mis_pilot" -q
Remove-Item Env:\QT_QPA_PLATFORM
```

`... passed` 로 끝나고 실패가 없으면 환경이 정상입니다. 1분 이내에 끝납니다.

`QT_QPA_PLATFORM = "offscreen"`은 화면 없이 테스트를 돌리라는 뜻입니다. 이것을 빼면
테스트 중에 창이 잠깐씩 나타납니다.

## 0.5 빌드하기

같은 PowerShell 창에서 아래 한 줄을 실행합니다.

```powershell
.\scripts\build.ps1
```

이 스크립트는 **`.\.venv\Scripts\python.exe`를 기본으로 사용합니다.** 0.4대로 만들었다면
따로 지정할 것이 없습니다. 가상환경을 다른 곳에 만들었다면 경로를 직접 넘기세요.

```powershell
.\scripts\build.ps1 -Python "C:\경로\python.exe"
```

이 명령 하나가 다음을 순서대로 자동으로 수행합니다.

1. **자동 검사** — 프로그램이 정상인지 시험합니다 (`automated gates`)
2. **형식 검사** — 코드 규칙과 타입을 확인합니다 (`lint, format, types`)
3. **부품 버전 확인** — 검증된 조합인지 확인합니다 (`toolchain pins`)
4. **모의 빌드** — 실제 빌드 전에 설정을 점검합니다 (`deploy dry run`)
5. **실제 빌드** — 실행 파일을 만듭니다 (`build`)

성공하면 마지막 줄에 이렇게 나옵니다.

```
built: E:\universal-rpa\dist\...\<프로그램이름>.exe
```

**이 경로를 메모해 두세요.** 다음 단계와 배포에 사용합니다.

> **왜 검사를 먼저 하나요**: 검사에 실패한 상태로 만들어진 실행 파일은 "없는 것보다 나쁩니다".
> 배포 가능한 것처럼 보이기 때문입니다. 그래서 검사가 하나라도 실패하면 빌드가 시작되지
> 않습니다.

**검사를 건너뛰고 빌드만 하고 싶다면** (급하게 다시 만들 때만 사용하세요):

```powershell
.\scripts\build.ps1 -SkipTests
```

## 0.6 만들어진 프로그램 점검하기

빌드가 끝나면 반드시 아래를 실행해 결과물이 제대로 만들어졌는지 확인합니다.

```powershell
.\scripts\smoke_packaged.ps1
```

이 명령은 만들어진 실행 파일을 **소스 폴더와 완전히 분리된 빈 폴더에서** 실행해 봅니다.
소스 폴더 옆에서 실행하면 껍데기만 든 빌드도 "성공"처럼 보이기 때문입니다.

마지막 줄에 아래가 나오면 정상입니다.

```
both packaged modes exited 0 from an empty CWD with no PYTHONPATH
```

중간에 나오는 `--self-check` 결과에서 네 항목이 모두 `"ok": true`인지도 확인하세요.

| 검사 항목 | 뜻 |
|---|---|
| `workflow_schema_v1` | 업무 저장 형식이 올바름 |
| `builtin_adapters` | 창 조작·클립보드·표 저장 기능이 모두 들어 있음 |
| `app_data_write` | 기록을 저장할 폴더에 쓸 수 있음 |
| `dpi_awareness` | 화면 배율을 정확히 인식함 |

## 0.7 사용자에게 나눠주기

1. `dist` 폴더 안에서 실행 파일(`.exe`)이 들어 있는 **폴더 전체**를 찾습니다.
2. 그 폴더를 마우스 오른쪽 버튼으로 클릭 → **압축(ZIP 파일로 압축)** 을 선택합니다.
3. 만들어진 ZIP 파일을 사용자에게 전달합니다.

> **주의: 실행 파일만 따로 빼내면 실행되지 않습니다.** 같은 폴더에 있는 나머지 파일들이
> 프로그램의 부품입니다. 항상 **폴더 통째로** 전달하세요.

전달할 때 사용자에게 이 설명서의 **1부**를 함께 주세요.

## 0.8 문제가 생겼을 때

### 0.8.1 환경 만들기(0.4)에서 막힐 때

| 화면에 나온 문구 | 원인 | 해결 |
|---|---|---|
| `Requires-Python >=3.12,<3.14` | `.venv`가 3.14로 만들어짐 | `.venv`를 지우고 `py -V:3.13 -m venv .venv`로 다시 생성 |
| `py : ... 인식할 수 없는` | Python 설치 관리자가 없음 | [0.3.2](#032-313-설치하기)의 ② 또는 ③ 방법으로 설치 |
| `No Python 3.13 found` / `py install` 실패 | 설치 관리자가 구형 launcher임 | [0.3.2](#032-313-설치하기)의 ② winget 또는 ③ 직접 내려받기 |
| `'python' 용어가 ... 인식되지 않습니다` | PATH에 등록되지 않음 | 설치 시 **Add python.exe to PATH**를 켜고 재설치, 또는 `py`를 사용 |
| `pip ... SSL` 또는 내려받기 실패 | 사내망 프록시·방화벽 | 네트워크 담당자에게 `pypi.org` 접근 허용 요청 |

### 0.8.2 빌드(0.5)에서 막힐 때

| 화면에 나온 문구 | 원인 | 해결 |
|---|---|---|
| `Python interpreter not found at ...` | 0.4를 실행하지 않았거나 `.venv`가 없음 | 0.4를 다시 수행 |
| `automated tests failed` | 소스에 문제가 있음 | 개발 담당자에게 전달. 이 상태로 배포하지 마세요 |
| `PySide6 is not pinned to 6.11.1` | 부품 버전이 다름 | `.\.venv\Scripts\python.exe -m pip install -e ".[dev,build]"` 다시 실행 |
| `Nuitka is ..., expected 4.1.3` | 같은 원인 | 위와 동일 |
| `pyside6-deploy.exe not found` | 설치가 덜 됨 | 위와 동일 |
| `workflow schema is out of date` | 저장 형식 정의가 코드와 어긋남 | 개발 담당자에게 전달 |
| `expected exactly one packaged executable, found 0` | 빌드가 실제로는 실패함 | 화면을 위로 올려 `WARNING`으로 시작하는 줄을 찾아 개발 담당자에게 전달 |
| 중간에 멈춘 채 진행되지 않음 | 백신이 검사 중이거나 컴파일러를 내려받는 중 | 10분 정도 더 기다려 보고, 계속 멈춰 있으면 작업 폴더를 백신 예외로 등록 후 재시도 |

# 1부. 사용자 설명서

## 1장. 이 프로그램이 하는 일과 하지 않는 일

### 1.1 할 수 있는 일

- Windows 프로그램(MIS, ERP, 사내 시스템 등)에서 **마우스 클릭·드래그·스크롤과
  키보드 입력**을 기록합니다.
- 기록한 동작을 **알아보기 쉬운 단계 목록**으로 정리해 보여 줍니다.
- 단계마다 이름을 붙이고, 값을 바꾸고, 실패했을 때 어떻게 할지 정할 수 있습니다.
- 실행할 때마다 바뀌는 값(날짜 등)을 **실행 변수**로 입력받습니다.
- Excel·CSV 목록을 따라 **여러 건을 반복** 처리합니다 (최대 2단계 중첩).
- 화면이 준비될 때까지 **기다렸다가** 다음 단계를 진행합니다.
- 실행 전에 **환경을 미리 점검**해서, 위험하면 아예 시작하지 않습니다.
- 실행 결과를 **보고서**로 남깁니다. 무엇이 성공하고 무엇이 실패했는지 알 수 있습니다.
- 비밀번호는 **Windows 자격 증명 관리자**에 맡기고, 프로그램은 참조만 저장합니다.

### 1.2 하지 않는 일 (중요)

이것들은 "아직 안 되는 것"이 아니라 **의도적으로 하지 않는 것**입니다.

| 하지 않는 일 | 이유 |
|---|---|
| 화면이 **잠긴 상태**에서 실행 | 사람이 로그인한 화면에서만 동작하도록 설계됨 |
| 관리자 권한 창(UAC), **2단계 인증(MFA), 보안문자(CAPTCHA)** 통과 | 보안 장치를 우회하지 않습니다. 로그인은 사람이 직접 합니다 |
| **정해진 시각에 자동 실행**(예약 실행) | 사용자가 로그인한 상태에서 직접 실행해야 합니다 |
| 화면을 **그림으로 보고 판단**(이미지 인식·OCR) | 정확도가 보장되지 않아 사용하지 않습니다 |
| 워크플로 안에서 **임의의 명령·프로그램 실행** | 안전을 위해 원천적으로 막혀 있습니다 |
| **승인·송금·삭제·권한 변경** 같은 되돌리기 어려운 업무 | 자동화 대상으로 삼지 마세요 |
| 인공지능(AI) 서버 통신 | 실행 중 외부 AI를 호출하지 않습니다. 완전히 내 컴퓨터 안에서 동작합니다 |
| macOS, Linux | Windows 10/11 64비트 전용입니다 |

### 1.3 자동화하기 좋은 업무 / 나쁜 업무

**좋은 업무**
- 매일 같은 화면에서 조건만 바꿔 **조회**하고 결과를 **복사·저장**하는 일
- 같은 양식에 **정해진 값을 입력**하는 일
- 여러 건을 같은 방식으로 **반복**하는 일

**나쁜 업무**
- 사람이 화면을 보고 **판단**해야 하는 일
- 실수했을 때 **되돌릴 수 없는** 일 (전송, 승인, 삭제)
- 화면 구성이 **자주 바뀌는** 프로그램

## 2장. 설치와 첫 실행

### 2.1 설치하기

이 프로그램은 별도의 설치 과정이 없습니다.

1. 전달받은 ZIP 파일을 마우스 오른쪽 버튼으로 클릭 → **압축 풀기**를 선택합니다.
2. 압축을 풀 위치는 **본인 문서 폴더 아래**를 권장합니다.
   예: `C:\Users\<내이름>\Documents\UniversalRPAStudio\`
3. `Program Files` 폴더나 바탕화면에는 두지 마세요. 권한 문제가 생길 수 있습니다.

> **폴더 통째로 유지하세요.** 안의 `.exe` 파일만 다른 곳으로 옮기면 실행되지 않습니다.
> 자주 쓰신다면 `.exe` 파일을 오른쪽 클릭 → **바로 가기 만들기**로 바탕화면에
> **바로 가기**만 두세요.

### 2.2 첫 실행

압축을 푼 폴더에서 `.exe` 파일을 두 번 클릭합니다.

**"Windows의 PC 보호" 파란 창이 뜬다면** — 인터넷에서 받은 새 프로그램이라 나오는
정상적인 안내입니다.

1. **추가 정보**를 클릭합니다.
2. 아래에 나타나는 **실행** 버튼을 클릭합니다.

> 이 창이 뜨는 것이 걱정되면 파일을 전달해 준 담당자에게 출처를 확인하세요.

잠시 뒤 **Universal RPA Studio** 창이 열리고, 왼쪽에 다섯 개의 메뉴가 보이면 정상입니다.

### 2.3 프로그램이 열리지 않을 때

프로그램은 스스로를 점검하는 기능을 가지고 있습니다. 결과를 **바탕화면에 파일로**
저장하는 방법입니다.

1. `Windows 키` → `powershell` 입력 → **Windows PowerShell** 실행
2. 아래를 붙여넣되, `<경로>` 자리에 실제 `.exe` 파일 경로를 넣고 Enter를 누릅니다.

```powershell
Start-Process -FilePath "<경로>\프로그램이름.exe" -ArgumentList "--self-check" -Wait `
  -RedirectStandardOutput "$env:USERPROFILE\Desktop\self-check.txt"
```

3. 바탕화면에 생긴 `self-check.txt` 파일을 엽니다.

네 항목이 모두 `"ok": true`로 나와야 정상입니다. 하나라도 `false`이면 **이 파일을 그대로**
배포 담당자에게 보내세요.

> 화면에 아무것도 안 나오는 것이 정상입니다. 이 프로그램은 명령 창에 글자를 출력하지
> 않도록 만들어져 있어서, 위처럼 파일로 저장해야 결과를 볼 수 있습니다.

## 4장. 10분 따라하기 — 메모장으로 첫 자동화 만들기

실제 업무 시스템에 적용하기 전에, **메모장**으로 한 번 연습해 보시길 강력히 권합니다.
잘못돼도 아무 피해가 없습니다.

### 준비

1. **메모장**을 엽니다 (`Windows 키` → `메모장` 입력 → Enter).
2. 메모장 창을 화면에 열어 둔 채로 Universal RPA Studio를 엽니다.

### 1단계 — 프로젝트 만들기

1. 왼쪽에서 **프로젝트**를 클릭합니다.
2. **새 프로젝트** 버튼을 누릅니다.
3. 폴더 선택 창이 뜹니다. **새 폴더를 하나 만들어** 선택하세요.
   예: `문서\RPA연습\메모장연습`
   → 반드시 **비어 있는 폴더**를 선택하세요.
4. 이름을 묻는 창에 `메모장 연습`이라고 입력하고 **확인**을 누릅니다.

✅ 화면에 프로젝트 이름과 폴더 경로, `리비전 1`이 표시되면 성공입니다.

### 2단계 — 업무 기록하기

1. 왼쪽에서 **기록**을 클릭합니다.
2. **창 목록 새로고침**을 누릅니다.
3. 위쪽 목록에서 **메모장** 창을 선택합니다.
   (`notepad.exe · 제목 없음 - 메모장` 형태로 표시됩니다.)
4. **기록 시작**을 누릅니다.
   → 화면에 `● 기록 중 · 제목 없음 - 메모장 · 00:03` 같은 빨간 안내가 나타납니다.
5. **메모장 창을 클릭해 활성화한 뒤**, 평소처럼 `안녕하세요`라고 입력합니다.
6. Studio로 돌아와 **기록 종료**를 누릅니다.
   (또는 어느 화면에서든 `Ctrl+Shift+F12`를 누르면 종료됩니다.)

✅ 아래에 표가 나타나고 `N개 동작을 감지했습니다`라는 안내가 보이면 성공입니다.

### 3단계 — 기록된 내용 확인하고 넘기기

표에는 네 개의 칸이 있습니다.

| 감지 동작 | 단계 이름 | 값/자격증명 | 대상 |
|---|---|---|---|
| `windows.click` | 클릭 | | 미리보기 없음 |
| `windows.set_text` | 텍스트 입력 | 안녕하세요 | 미리보기 없음 |

1. **단계 이름** 칸을 알아보기 쉽게 고칩니다. 예: `메모장 본문 클릭`, `인사말 입력`.
2. **값/자격증명** 칸의 내용이 실제로 입력한 글자와 같은지 확인합니다.
3. **검토 내용을 편집기로 가져오기** 버튼을 누릅니다.

✅ `검토한 동작을 편집기로 전달했습니다`라고 나오면 성공입니다.

### 4단계 — 확인하고 저장하기

1. 왼쪽에서 **편집**을 클릭합니다. 왼쪽 목록에 방금 지은 이름들이 보입니다.
2. 단계를 하나 클릭하면 오른쪽에 상세 내용이 나옵니다.
3. **환경 검사** 버튼을 눌러 문제가 없는지 확인합니다.

4. **`Ctrl+S`** 를 누르거나 **파일 → 프로젝트 저장**을 선택해 저장합니다.

✅ 상태 표시줄에 `프로젝트를 저장했습니다: 메모장 연습`이 나오면 저장된 것입니다.

### 5단계 — 실행하기

1. 메모장의 기존 내용을 지우고 빈 상태로 만들어 둡니다.
2. 왼쪽에서 **실행**을 클릭합니다.
3. **출력 폴더 선택**을 눌러 **비어 있는 새 폴더**를 지정합니다.
   예: `문서\RPA연습\결과`
4. **사전 검증**을 누릅니다.
   ✅ `사전 검증을 통과했습니다`가 나오면 **실행** 버튼이 활성화됩니다.
5. **실행**을 누릅니다.
   → 마우스와 키보드가 저절로 움직입니다. **손대지 말고 지켜보세요.**
   → 멈추고 싶으면 `Ctrl+Shift+F12`를 누릅니다.

✅ 메모장에 `안녕하세요`가 자동으로 입력되고, 화면이 **보고서**로 바뀌면 성공입니다.

### 6단계 — 결과 확인

**보고서** 화면에서 **상태**가 `성공`인지 확인합니다.

축하합니다. 첫 자동화를 완성했습니다. 이제 각 단계를 자세히 알아봅니다.

## 6장. 업무 기록하기

### 6.1 기록하기 전에

기록은 **실제 업무를 한 번 시연하는 과정**입니다. 시작하기 전에 정리하세요.

- [ ] 자동화할 프로그램을 **미리 열어 두고 로그인**해 둡니다.
- [ ] 시작 화면을 **매번 같은 상태**로 맞춰 둡니다. (예: 항상 메인 화면에서 시작)
- [ ] 무엇을 어떤 순서로 할지 **머릿속으로 한 번 정리**합니다.
- [ ] 기록 중에는 **다른 창을 건드리지 않습니다.**

> **왜 시작 상태가 중요한가요**: 자동화는 기록할 때와 **같은 화면에서 시작**한다고
> 가정하고 동작합니다. 시작 화면이 다르면 엉뚱한 곳을 클릭하게 됩니다.

### 6.2 기록 순서

1. **기록** 메뉴로 이동합니다.
2. **창 목록 새로고침**을 누릅니다.
3. 목록에서 **자동화할 창**을 선택합니다.
   표시 형식: `프로그램파일이름.exe · 창 제목`
4. **기록 시작**을 누릅니다.
5. 대상 창으로 이동해 **평소처럼 업무를 수행**합니다.
6. 끝나면 **기록 종료**를 누릅니다.

### 6.3 기록 중 화면 표시

기록이 시작되면 이런 안내가 계속 표시됩니다.

```
● 기록 중 · 생산관리시스템 · 01:24
Ctrl+Shift+F11 일시정지/계속 · Ctrl+Shift+F12 종료
```

| 단축키 | 기능 | 어디서든 되나요 |
|---|---|---|
| `Ctrl+Shift+F11` | 일시정지 / 다시 시작 | 예 |
| `Ctrl+Shift+F12` | 기록 종료 | 예 |

**일시정지를 활용하세요.** 기록하고 싶지 않은 작업(다른 창 확인, 전화 받기 등)이 생기면
`Ctrl+Shift+F11`로 멈췄다가 다시 시작하면 됩니다.

> 이 단축키 자체는 기록되지 않습니다. 자동화 단계에 섞여 들어가지 않습니다.

### 6.4 기록되는 것과 되지 않는 것

**기록됩니다**
- 클릭, 더블클릭, 드래그, 마우스 휠
- 글자 입력, Enter·Tab·방향키 같은 특수키, `Ctrl+C` 같은 단축키

**기록되지 않습니다**
- **선택한 창 밖에서 한 동작** — 다른 창을 클릭해도 자동화에 포함되지 않습니다
- **마우스를 그냥 움직인 것** — 클릭하지 않은 이동은 무시됩니다
- **비밀번호 칸에 입력한 실제 글자** — 자리표시자만 남습니다 ([10장](#10장-비밀번호-안전하게-사용하기) 참고)

### 6.5 기록 결과 검토하기

기록을 마치면 감지된 동작이 표로 나타납니다.

| 칸 | 뜻 | 할 일 |
|---|---|---|
| **감지 동작** | 시스템이 판단한 동작 종류 | 확인만 (수정 불가) |
| **단계 이름** | 목록에 표시될 이름 | **알아보기 쉽게 고치세요** |
| **값/자격증명** | 입력한 글자 | 실제 값과 같은지 확인 |
| **대상** | 클릭 위치 미리보기 | 확인만 |

**단계 이름은 반드시 고치세요.** `클릭`, `텍스트 입력` 같은 기본 이름이 20개 있으면
나중에 아무도 알아볼 수 없습니다. `조회 버튼 클릭`, `시작일 입력`처럼 적으세요.

동작 종류는 다음과 같이 표시됩니다.

| 표시 | 뜻 |
|---|---|
| `windows.click` | 클릭 |
| `windows.double_click` | 더블클릭 |
| `windows.drag` | 드래그 |
| `windows.scroll` | 스크롤 |
| `windows.set_text` | 글자 입력 |
| `windows.press_key` | 특수키 입력 (Enter, Tab 등) |
| `windows.hotkey` | 단축키 입력 (Ctrl+C 등) |

검토가 끝나면 **검토 내용을 편집기로 가져오기**를 누릅니다.

### 6.6 한글 입력에 대해

한글은 자판을 그대로 재현하는 방식으로는 정확히 옮겨지지 않습니다. 그래서 이 프로그램은
**완성된 글자를 읽어서** 저장합니다.

- 대부분의 입력창에서는 완성된 한글이 정확히 기록됩니다.
- 특수하게 만들어진 입력창에서는 값이 이상하게 보일 수 있습니다.
  이때는 **값/자격증명 칸에서 직접 올바른 글자로 고쳐 주세요.**

## 7장. 단계 다듬기

**편집** 화면은 세 부분으로 나뉩니다.

```
┌─────────────┬──────────────────┬──────────────────┐
│ 단계 목록   │  대상 미리보기   │  선택한 단계의   │
│             │                  │  상세 설정       │
│ 1 로그인    │  [클릭 위치가    │                  │
│ 2 조회 클릭 │   표시된 화면    │  단계 이름 [   ] │
│ 3 결과 복사 │   그림]          │  활성 상태 [v]   │
│             │                  │  값 종류   [  v] │
└─────────────┴──────────────────┴──────────────────┘
```

위쪽에는 네 개의 버튼이 있습니다.

| 버튼 | 하는 일 | 언제 쓰나 |
|---|---|---|
| **JSON 보기** | 내부 저장 형식을 그대로 보여 줍니다 (읽기 전용) | 문의할 때 내용을 확인·복사할 용도 |
| **대상 다시 지정** | 클릭할 대상을 다시 잡습니다 | 화면이 바뀌어 대상을 못 찾을 때 |
| **선택 단계 테스트** | 그 단계만 한 번 실행해 봅니다 | 한 단계가 의심스러울 때 |
| **환경 검사** | 지금 실행해도 되는지 점검합니다 | 편집을 마친 뒤 항상 |
| **실행 변수 추가** | 실행할 때마다 바뀌는 값을 정의합니다 | [11.1](#111-실행-변수-만들기--실행할-때마다-값-바꾸기) |
| **선택 단계 반복 만들기** | 선택한 단계를 목록만큼 반복시킵니다 | [11.2](#112-반복-실행--여러-건을-한-번에) |

### 7.1 단계 이름과 실행 여부

- **단계 이름** — 목록에 나올 이름입니다. 비워 둘 수 없습니다.
- **활성 상태** — 체크를 해제하면 그 단계를 **건너뜁니다**. 지우지 않고 잠시 빼 둘 때
  유용합니다.

바꾼 뒤에는 아래 **변경 적용** 버튼을 눌러야 반영됩니다.

### 7.2 값 종류 고르기

**값 종류**는 그 단계가 입력할 값을 **어디서 가져올지** 정합니다.

| 값 종류 | 뜻 | 예 |
|---|---|---|
| **고정값** | 항상 똑같은 값 | 부서명 `생산1팀` |
| **실행 변수** | 실행할 때마다 사람이 입력 | 조회 시작일 |
| **반복 열** | 목록 파일의 각 행에서 가져옴 | 공장 코드 목록 |
| **비밀값** | Windows 자격 증명 관리자에서 가져옴 | 로그인 비밀번호 |
| **값 없음** | 값이 필요 없는 동작 | 버튼 클릭 |

기록 직후에는 모든 글자 입력이 **고정값**입니다. 매번 바뀌는 값이라면 종류를 바꿔야
합니다.

> **실행 변수**와 **반복 열**은 먼저 변수 또는 데이터 소스를 만들어 두어야 합니다.
> 만들지 않고 종류만 바꾸면 사전 검증에서 실패합니다.
> 만드는 방법은 [11장](#11장-실행-변수와-반복-실행)에 있습니다.

### 7.3 실패했을 때 어떻게 할지 정하기

| 실패 처리 | 뜻 | 언제 쓰나 |
|---|---|---|
| `stop` | 즉시 전체 중단 (**기본값**) | 대부분의 경우. 가장 안전합니다 |
| `retry` | 정해진 횟수만큼 다시 시도 | 화면이 가끔 느려서 실패하는 단계 |
| `skip_iteration` | 이 건은 포기하고 다음 건으로 | 반복 실행에서 일부 실패를 허용할 때 |

`retry`를 고르면 **재시도 횟수**(0~3회)를 정할 수 있습니다.

> **기본값 `stop`을 바꾸기 전에 한 번 더 생각하세요.** 실패했는데도 계속 진행하면
> 잘못된 결과가 정상처럼 쌓입니다. 이 프로그램의 기본 원칙은 **"의심스러우면 멈춘다"**
> 입니다.

### 7.4 대상 다시 지정하기

프로그램 화면이 업데이트되어 버튼 위치나 모양이 바뀌면 자동화가 대상을 못 찾습니다
(`target_not_found`). 이때 **대상 다시 지정**으로 새 위치를 잡아 줍니다.

1. 대상을 바꿀 **단계를 선택**합니다.
2. **대상 다시 지정**을 누릅니다. 캡처 창이 열립니다.
3. **대상 캡처**를 누릅니다. `3초 후 마우스 위치를 캡처합니다`가 표시됩니다.
4. **3초 안에 마우스를 새 대상 위로 옮기고 그대로 둡니다.** (클릭하지 마세요.)
5. 시간이 지나면 그 위치의 대상 후보가 목록에 나타납니다.
6. 목록에서 후보를 하나 고릅니다.
7. 가려야 할 부분이 있으면 민감 영역 목록에서 확인합니다.
   비밀번호 칸은 **필수 잠금**으로 표시되며 해제할 수 없습니다.
8. **OK**를 누릅니다.

✅ 성공하면 새 대상과 미리보기가 **자동 저장**됩니다.

> 자동화할 프로그램 창이 **화면에 보이는 상태**여야 합니다. 최소화되어 있으면 캡처할 수
> 없습니다.

### 7.5 저장하는 방법

단계를 고치면 화면 아래 상태 표시줄에 이렇게 나옵니다.

```
프로젝트에 저장되지 않은 변경이 있습니다.
```

저장 방법은 두 가지입니다.

| 방법 | 조작 |
|---|---|
| 메뉴 | 창 위쪽 **파일 → 프로젝트 저장** |
| 단축키 | **`Ctrl+S`** |

✅ 상태 표시줄에 `프로젝트를 저장했습니다: <업무이름>`이 나오면 저장된 것입니다.

**저장하지 않고 창을 닫으려 하면** `현재 프로젝트 변경 내용을 저장할까요?` 창이 뜹니다.

| 버튼 | 결과 |
|---|---|
| **Save** | 저장하고 닫습니다 |
| **Discard** | **저장하지 않고 버립니다** |
| **Cancel** | 닫기를 취소합니다 |

**비밀값 지정**과 **대상 다시 지정**은 별도로 누르지 않아도 성공 시 **자동 저장**됩니다.

> **참고**: 편집한 내용은 저장 전에도 **실행** 화면에 곧바로 반영됩니다. 다만 단계를 고치면
> 이전 **사전 검증** 결과는 무효가 되므로, 실행 전에 **사전 검증**을 다시 눌러야 합니다.

## 8장. 실행하기

### 8.1 실행 전 확인 목록

- [ ] 편집한 내용을 **저장**했습니다 (`Ctrl+S`).
- [ ] 자동화할 프로그램이 **열려 있고 로그인**되어 있습니다.
- [ ] 시작 화면이 **기록할 때와 같은 상태**입니다.
- [ ] **화면 배율과 해상도**가 기록할 때와 같습니다.
- [ ] 실행 중 **사용하지 않아도 되는 시간**을 확보했습니다.
- [ ] 결과를 저장할 **비어 있는 폴더**를 준비했습니다.

### 8.2 실행 순서

**① 출력 폴더 선택**

**출력 폴더 선택** 버튼을 눌러 결과 파일이 저장될 폴더를 지정합니다.

> ⚠️ **반드시 비어 있는 새 폴더를 고르세요.** 기존 업무 파일이 있는 폴더를 지정하면
> 덮어쓸 위험이 있습니다.

폴더를 고를 수 없다는 안내가 나오면 [12장](#12장-문제-해결)을 보세요.

**② 자격 증명 확인**

이 업무가 비밀번호를 쓴다면 **자격 증명 참조**란에 이름이 표시됩니다.
등록되지 않았으면 **자격 증명 관리자 열기** 버튼이 나타납니다.
→ [10장](#10장-비밀번호-안전하게-사용하기)을 보고 등록하세요.

**③ 실행 입력 채우기**

**실행 입력** 상자가 보이면 이번 실행에 쓸 값을 채웁니다. (날짜는 달력에서 고릅니다.)
이 상자가 없으면 입력할 값이 없는 업무입니다.

**④ 사전 검증**

**사전 검증** 버튼을 누릅니다. 이때는 **마우스·키보드를 전혀 조작하지 않고** 점검만 합니다.

점검 항목은 다음과 같습니다.

1. 업무 내용을 읽을 수 있는가
2. 필요한 기능이 모두 설치되어 있는가
3. 대상 프로그램과 창을 정확히 하나로 찾을 수 있는가
4. 클릭할 대상을 찾을 수 있는가
5. 입력값과 반복 목록이 올바른가
6. 비밀번호가 등록되어 있는가
7. 출력 폴더에 저장할 수 있는가
8. 저장할 파일이 다른 프로그램에 잠겨 있지 않은가

✅ `사전 검증을 통과했습니다`가 나오면 **실행** 버튼이 켜집니다.
❌ 실패하면 이유가 표시되고 **실행 버튼은 켜지지 않습니다.**

> **이 설계가 지켜 주는 것**: 점검에 실패하면 **클릭을 단 한 번도 하지 않습니다.**
> 엉뚱한 곳을 눌러 사고가 나는 상황을 원천적으로 막습니다.

**⑤ 실행**

**실행** 버튼을 누릅니다.

- 마우스와 키보드가 자동으로 움직입니다. **손대지 마세요.**
- 진행 상황이 표시됩니다: `실행 중 · 완료 12 · 실패 0 · 최근 단계 조회 버튼 클릭`

### 8.3 실행 중 조작

| 조작 | 방법 | 효과 |
|---|---|---|
| 일시정지 / 계속 | **일시정지** 버튼 또는 `Ctrl+Shift+F11` | 잠시 멈췄다가 이어서 진행 |
| 중지 | **중지** 버튼 또는 `Ctrl+Shift+F12` | 지금까지 한 것을 기록하고 멈춤 |

**급할 때는 `Ctrl+Shift+F12`를 누르세요.** 어느 창에 있든 동작하며, 다른 모든 작업보다
우선 처리됩니다.

> 실행 중에 다른 창을 클릭하면 자동화가 **실패로 멈춥니다**. 잘못된 창에 입력이 들어가는
> 것을 막기 위한 안전장치입니다. 실행 중에는 컴퓨터를 사용하지 마세요.

### 8.4 문제가 생겼을 때 쓰는 두 버튼

| 버튼 | 하는 일 | 켜지는 조건 |
|---|---|---|
| **실패 단계 재시도** | 실패한 그 단계만 다시 실행 | 마지막 실행에 실패한 단계가 있을 때 |
| **이어서 실행** | 중단된 지점부터 계속 | 중단된 실행 기록이 있고, 이어서 해도 안전할 때 |

**이어서 실행 버튼이 켜지지 않는다면** 안내 문구를 읽어 보세요.

`자동 재개를 사용할 수 없으니 수동으로 확인하세요`라고 나오면 — 중단된 지점이
**한 건의 처리 도중**이라서, 이어서 하면 같은 작업을 두 번 할 위험이 있다는 뜻입니다.
이때는 **직접 화면을 확인해 어디까지 처리됐는지 파악한 뒤** 판단하세요.

> **안전하게 멈추는 요령**: `Ctrl+Shift+F12`는 **한 건의 처리가 막 끝난 직후**에 누르세요.
> 처리 도중에 멈추면 이어서 실행할 수 없습니다.

## 9장. 보고서 읽기

실행이 끝나면 자동으로 **보고서** 화면으로 이동합니다.

### 9.1 요약

| 항목 | 뜻 |
|---|---|
| **업무** | 업무 이름과 리비전 번호 |
| **실행 ID** | 이번 실행의 고유 번호 (문의할 때 알려 주세요) |
| **상태** | 전체 결과 (아래 표 참고) |
| **전체/성공/실패/건너뛴 반복** | 여러 건 처리 시 각각의 건수 |
| **실행한 단계 수** | 실제로 수행된 동작 수 |
| **마지막 체크포인트** | 어디까지 확실히 끝났는지 |
| **실행 환경** | 실행한 컴퓨터 환경 정보 |
| **안내** | 사람이 읽을 수 있는 설명 |

**상태** 값은 네 가지입니다.

| 상태 | 뜻 | 해야 할 일 |
|---|---|---|
| **성공** | 모두 정상 완료 | 결과 파일 확인 |
| **부분 성공** | 일부 건을 의도적으로 건너뜀 | 건너뛴 건을 직접 처리 |
| **실패** | 문제가 생겨 중단됨 | 아래 실패 표 확인 |
| **중지됨** | 사람이 중지시킴 | 필요하면 **이어서 실행** |

### 9.2 산출물

만들어진 결과 파일 목록입니다.

| 칸 | 뜻 |
|---|---|
| **산출물 경로** | 출력 폴더 기준 파일 위치 |
| **형식** | CSV 또는 XLSX |
| **시트** | Excel 시트 이름 |
| **행 수** | 저장된 데이터 줄 수 |
| **내용 해시** / **머리글 해시** | 파일이 바뀌지 않았음을 증명하는 지문 |

> **행 수를 꼭 확인하세요.** 평소 100줄이 나오던 업무에서 3줄만 나왔다면, 실행은
> "성공"이어도 조회 조건이 잘못됐을 수 있습니다.

**해시**란 파일 내용을 요약한 고유한 문자열입니다. 내용이 한 글자라도 바뀌면 완전히
달라집니다. 결과 파일이 나중에 변조되지 않았는지 확인할 때 씁니다.

### 9.3 실패한 단계

| 칸 | 뜻 |
|---|---|
| **단계** | 실패한 단계 이름 |
| **반복 위치** | 몇 번째 건에서 실패했는지 |

| **오류 코드** | 실패 원인 분류 ([12.3](#123-오류-코드-뜻) 참고) |

### 9.4 보고서 내보내기

**보고서 내보내기** 버튼으로 결과를 파일로 저장할 수 있습니다.

이 파일에는 **비밀번호, 입력한 글자 원문, 복사한 표의 내용, 창 제목이 들어 있지
않습니다.** 그대로 담당자나 개발자에게 전달해도 안전합니다.

## 10장. 비밀번호 안전하게 사용하기

### 10.1 어떻게 보호되나요

이 프로그램은 **비밀번호를 저장하지 않습니다.** Windows가 원래 가지고 있는
**자격 증명 관리자**에 맡기고, "그 이름의 비밀번호를 꺼내 써라"라는 **이름표만** 저장합니다.

그래서 다음 어디에도 비밀번호가 남지 않습니다.

- 업무 파일(`workflow.json`)
- 기록 원본
- 실행 기록과 보고서
- 실패 화면 캡처

또한 비밀번호 입력칸(●●●로 보이는 칸)에 입력한 글자는 **기록 자체를 하지 않습니다.**

### 10.2 비밀번호 등록하기

**① 이름 확인**

**실행** 화면의 **자격 증명 참조**란에 표시된 이름을 확인합니다. 이 이름과 **똑같이**
등록해야 합니다.

**② 자격 증명 관리자 열기**

- **실행** 화면의 **자격 증명 관리자 열기** 버튼을 누르거나,
- `Windows 키` → `자격 증명 관리자` 입력 → Enter

**③ 등록**

1. **Windows 자격 증명**을 클릭합니다.
2. **일반 자격 증명 추가**를 클릭합니다.
3. 아래처럼 입력합니다.

| 칸 | 입력할 내용 |
|---|---|
| 인터넷 또는 네트워크 주소 | **자격 증명 참조에 표시된 이름 그대로** |
| 사용자 이름 | 해당 시스템의 아이디 |
| 암호 | 해당 시스템의 비밀번호 |

4. **확인**을 누릅니다.

**④ 확인**

Studio로 돌아와 **사전 검증**을 다시 누릅니다. `자격 증명 관리자 열기` 버튼이 사라지면
정상 등록된 것입니다.

### 10.3 일반 입력칸을 비밀값으로 바꾸기

비밀번호 칸이 아니어서 그냥 기록됐지만 민감한 값(주민번호, 계좌번호 등)이라면
직접 비밀값으로 바꿀 수 있습니다.

1. **편집** 화면에서 해당 단계를 선택합니다.
2. **값 종류**를 **비밀값**으로 바꿉니다.
3. 값 칸에 **자격 증명 이름**을 입력합니다. (입력하는 글자는 ●로 가려집니다.)
4. **변경 적용**을 누릅니다.

이때 프로그램이 함께 처리하는 것:

- 관련된 **기록 원본을 삭제**합니다.
- 대상 미리보기 그림에서 그 부분을 **가립니다**.
- 프로젝트를 **자동 저장**합니다.

## 11장. 실행 변수와 반복 실행

이 장은 **매번 값이 바뀌는 업무**와 **여러 건을 처리하는 업무**를 다룹니다.
모두 **편집** 화면에서 설정합니다.

### 11.1 실행 변수 만들기 — 실행할 때마다 값 바꾸기

조회 날짜처럼 실행할 때마다 달라지는 값에 사용합니다.

1. **편집** 화면에서 **실행 변수 추가**를 누릅니다.
2. 아래를 채웁니다.

| 칸 | 뜻 | 예 |
|---|---|---|
| **변수 ID** | 내부 이름 (영문·숫자·밑줄) | `start_date` |
| **화면 이름** | 실행 화면에 표시될 이름 | `조회 시작일` |
| **값 종류** | 값의 형태 | `date` |
| **입력 방식** | 값을 어디서 가져올지 | `run_input` (실행 전 직접 입력) |

3. **확인**을 누릅니다.
4. 그 값을 입력할 **단계를 선택**하고, **값 종류**를 **실행 변수**로 바꾼 뒤
   **값/ID/열** 칸에 **변수 ID**를 그대로 적고 **변경 적용**을 누릅니다.

✅ **실행** 화면의 **실행 입력** 상자에 방금 만든 이름이 나타나면 성공입니다.
날짜 변수는 달력에서 고를 수 있습니다.

**입력 방식** 종류

| 입력 방식 | 뜻 |
|---|---|
| `run_input` | 실행 전에 사람이 직접 입력 |
| `fixed_default` | 항상 같은 기본값 |
| `inline_options` | 미리 정한 목록에서 선택 |
| `csv_column` / `xlsx_column` | 목록 파일의 열에서 가져옴 |
| `date_rule` | 오늘·월초·월말 등 날짜 계산 |
| `credential_ref` | Windows 자격 증명 관리자에서 조회 |

### 11.2 반복 실행 — 여러 건을 한 번에

공장 목록, 거래처 목록처럼 **같은 작업을 목록만 바꿔 반복**할 때 사용합니다.

**① 목록 파일 준비**

CSV 또는 Excel 파일을 만들어 **프로젝트 폴더 안**에 둡니다.
예: `<프로젝트폴더>\inputs\factories.csv`

```
공장,기간
1공장,2026-08
2공장,2026-08
```

첫 줄은 반드시 **열 이름**이어야 합니다.

**② 반복 만들기**

1. **편집** 화면의 왼쪽 목록에서 **반복할 단계들을 선택**합니다.
   (`Ctrl`을 누른 채 클릭하면 여러 개, `Shift`+클릭이면 범위 선택입니다.)
2. **선택 단계 반복 만들기**를 누릅니다.
3. 아래를 채웁니다.

| 칸 | 뜻 | 예 |
|---|---|---|
| **반복 이름** | 목록에 표시될 이름 | `공장별 반복` |
| **데이터 소스 ID** | 내부 이름 (영문·숫자·밑줄) | `factories` |
| **소스 종류** | `csv` / `xlsx` / `inline` | `csv` |
| **파일 경로** | **프로젝트 폴더 기준 상대 경로** | `inputs/factories.csv` |
| **CSV 인코딩** | 파일 저장 형식 | 한글 Excel 저장 파일은 보통 `cp949` |
| **시트 이름** | Excel일 때만 | `Sheet1` |
| **최대 반복 횟수** | 안전 상한 | 기본 1,000 |
| **최대 실행 시간(초)** | 안전 상한 | 기본 7,200 (2시간) |

4. **확인**을 누릅니다.

✅ 선택한 단계들이 반복 이름 아래로 묶여 들어가면 성공입니다.

**③ 각 행의 값 사용하기**

반복 안의 단계를 선택하고 **값 종류**를 **반복 열**로 바꾼 뒤, **값/ID/열** 칸에
**열 이름**(예: `공장`)을 적고 **변경 적용**을 누릅니다.

> **파일 경로는 반드시 상대 경로로** 적으세요. `C:\...` 같은 절대 경로나 `..`는 거부됩니다.
> 목록 파일은 프로젝트 폴더 안에 두어야 합니다.

**인라인 목록**을 고르면 파일 없이 직접 적을 수도 있습니다.
- 인라인 열 이름: `공장,기간`
- 인라인 행: `1공장,2026-08;2공장,2026-08` (행은 `;`, 값은 `,`)

### 11.3 대기·검증 조건 — 화면이 준비될 때까지 기다리기

조회 결과가 뜨기 전에 다음 단계가 실행되어 실패하는 것을 막습니다.
단계를 선택하면 오른쪽 속성 아래에 나옵니다.

| 칸 | 뜻 |
|---|---|
| **대기 조건** | 무엇을 기다릴지 (`사용 안 함`이면 기다리지 않음) |
| **조건 기대값** | 조건이 값을 비교할 때 쓰는 값 (선택) |
| **대기 시간(ms)** | 최대 대기 시간. 기본 30,000 (30초) |
| **결과 검증** | 실행 후 결과가 맞는지 확인할 항목 |
| **검증 기대값** | 검증이 기대하는 값 (선택) |

고른 뒤 **변경 적용**을 누릅니다.

> 목록에는 **실제로 지원되는 조건만** 표시됩니다. 무한 대기는 허용되지 않으며,
> 대기 시간이 지나면 `condition_timeout`으로 실패합니다.

### 11.4 아직 화면에서 할 수 없는 것

| 기능 | 대안 |
|---|---|
| 단계 추가·삭제·순서 변경 | 다시 기록하거나, **활성 상태** 체크를 꺼서 단계를 건너뜁니다 |
| 단계 합치기·나누기 | 위와 동일 |
| 3단계 이상 중첩 반복 | 지원하지 않습니다 (최대 2단계) |

## 12장. 문제 해결

### 12.1 기록할 때

| 증상 | 원인 | 해결 |
|---|---|---|
| 창 목록에 대상 프로그램이 없음 | 프로그램이 꺼져 있거나 최소화됨 | 창을 열어 두고 **창 목록 새로고침** |
| `현재 Windows 창 목록을 불러올 수 없습니다` | 권한 문제 | Studio를 껐다가 다시 실행 |
| `기록할 대상 창을 선택하세요` | 창을 안 골랐음 | 목록에서 창을 선택 후 다시 시도 |
| 동작이 하나도 감지되지 않음 | **선택한 창 밖에서 작업함** | 대상 창을 클릭해 활성화한 뒤 작업 |
| 한글이 깨져 기록됨 | 특수한 입력창 | 검토 표의 **값** 칸에서 직접 수정 |
| 비밀번호가 빈칸으로 나옴 | **정상 동작입니다** | [10장](#10장-비밀번호-안전하게-사용하기) 참고 |

### 12.2 실행할 때

| 증상 | 원인 | 해결 |
|---|---|---|
| **실행** 버튼이 회색 | 사전 검증을 안 했거나 실패함 | **사전 검증**을 눌러 통과시키기 |
| 단계를 고친 뒤 실행 버튼이 다시 회색 | **정상입니다.** 이전 검증 결과가 무효가 됨 | **사전 검증**을 다시 누르기 |
| 같은데도 계속 회색 | 출력 폴더 미선택 또는 비밀번호 미등록 | 출력 폴더 선택 / 자격 증명 등록 |
| `사용할 수 있는 출력 폴더가 아닙니다` | 폴더가 없거나 바로가기 폴더임 | 실제 폴더를 새로 만들어 선택 |
| `출력 폴더에 파일을 만들 수 없습니다` | 쓰기 권한 없음 | 내 문서 아래에 폴더를 만들어 선택 |
| 실행 도중 갑자기 멈춤 | 실행 중 다른 창을 클릭함 | **안전장치입니다.** 다시 실행하고 손대지 않기 |
| 엉뚱한 곳을 클릭함 | 시작 화면 상태가 다름 | 기록할 때와 같은 화면에서 다시 실행 |
| 화면 크기·배율을 바꾼 뒤 실패 | 좌표 기준이 달라짐 | 원래 배율로 되돌리거나 다시 기록 |
| **이어서 실행**이 회색 | 이어서 하면 위험한 지점에서 멈춤 | 직접 확인 후 판단 |

### 12.3 오류 코드 뜻

보고서의 **오류 코드** 칸에 나오는 값입니다.

| 코드 | 뜻 | 해결 |
|---|---|---|
| `target_not_found` | 클릭할 대상을 못 찾음 | 화면 상태 확인. 프로그램이 바뀌었다면 다시 기록 |
| `target_ambiguous` | 같은 대상이 여러 개 발견됨 | 화면에 같은 창이 여러 개 떠 있는지 확인 |
| `environment_mismatch` | 기록할 때와 환경이 다름 | 화면 배율·해상도·창 크기를 원래대로 |
| `foreground_mismatch` | 다른 창이 앞에 나옴 | 실행 중 컴퓨터를 사용하지 않기 |
| `condition_timeout` | 기다렸는데 화면이 준비되지 않음 | 시스템이 느린 상태. 잠시 후 재시도 |
| `assertion_failed` | 결과가 기대와 다름 | 조회 조건과 결과 화면 확인 |
| `secret_missing` | 비밀번호가 등록되지 않음 | [10장](#10장-비밀번호-안전하게-사용하기) 참고 |
| `output_unavailable` | 결과 파일을 저장할 수 없음 | **결과 파일이 Excel에 열려 있는지 확인 후 닫기** |
| `data_source_invalid` | 목록 파일에 문제가 있음 | CSV/Excel 파일의 열 이름 확인 |
| `adapter_missing` | 필요한 기능이 설치되지 않음 | 배포 담당자에게 문의 |
| `resume_unsafe` | 이어서 하면 중복 위험 | 자동 재개하지 말고 직접 확인 |
| `resume_mismatch` | 업무 내용이 바뀌어 이어서 못 함 | 처음부터 다시 실행 |
| `cancelled` | 사람이 중지시킴 | 정상. 필요하면 **이어서 실행** |
| `internal_error` | 예상치 못한 오류 | 보고서를 내보내 담당자에게 전달 |

### 12.4 문의할 때 보낼 것

다음 세 가지를 함께 보내면 원인을 훨씬 빨리 찾을 수 있습니다.

1. **보고서 내보내기**로 저장한 파일 (비밀번호·업무 내용이 들어 있지 않아 안전합니다)
2. **실행 ID** (보고서 요약에 있습니다)
3. 무엇을 하다가 언제 문제가 생겼는지 한두 줄 설명

> **화면 전체를 캡처해 보내지 마세요.** 업무 정보가 그대로 노출될 수 있습니다.
> 내보낸 보고서 파일이면 충분합니다.

1. **처음에는 반드시 연습용으로 시험하세요.** 실제 업무 화면에서 바로 시작하지 마세요.
2. **되돌릴 수 없는 업무는 자동화하지 마세요.** 전송, 승인, 삭제, 권한 변경.
3. **출력 폴더는 항상 비어 있는 새 폴더로.** 기존 업무 파일이 있는 곳은 피하세요.
4. **실행 중에는 컴퓨터를 쓰지 마세요.** 다른 창을 클릭하면 실행이 멈춥니다.
5. **결과를 항상 확인하세요.** 특히 **행 수**가 평소와 비슷한지 보세요.
6. **비밀번호는 반드시 자격 증명 관리자에 등록하세요.** 고정값으로 넣지 마세요.

### 13.2 무엇이 어디에 저장되나요

| 데이터 | 위치 | 보관 기간 |
|---|---|---|
| 업무 내용 (`workflow.json`) | 내가 만든 **프로젝트 폴더** | 직접 지울 때까지 |
| 대상 미리보기 그림 | 프로젝트 폴더 | 직접 지울 때까지 |
| **기록 원본** | `%LOCALAPPDATA%\UniversalRPAStudio\recordings\` | **7일** |
| 실행 기록·보고서·실패 화면 | 프로그램 데이터 폴더 | **30일** |
| 결과 파일 (CSV/Excel) | 내가 지정한 **출력 폴더** | 직접 관리 |
| 비밀번호 | **Windows 자격 증명 관리자** | 직접 지울 때까지 |

`%LOCALAPPDATA%` 폴더를 열려면 파일 탐색기 주소창에 그대로 붙여넣고 Enter를 누르세요.

**삭제 시점**: 보관 기간이 지난 자료는 **프로그램을 실행할 때** 자동으로 정리됩니다.
프로그램을 오래 켜지 않으면 그동안은 남아 있습니다.

### 13.3 업무를 다른 사람과 공유할 때

**프로젝트 폴더만** 전달하세요. 기록 원본과 실행 결과는 포함하지 마세요.

프로젝트 폴더에는 비밀번호가 들어 있지 않습니다. 다만 받는 사람은 **자기 컴퓨터의
자격 증명 관리자에 같은 이름으로 비밀번호를 직접 등록**해야 실행할 수 있습니다.

### 13.4 결과 파일이 안전하게 저장되는 방식

결과 파일은 다음 순서로 저장됩니다.

1. 먼저 **임시 파일**로 저장합니다.
2. 내용과 줄 수가 올바른지 **검사**합니다.
3. 검사를 통과해야 **진짜 파일로 바꿉니다**.

그래서 실행이 중간에 실패해도 **이전에 잘 저장된 결과 파일은 그대로 남습니다.**
반쯤 쓰다 만 파일이 정상 파일처럼 보이는 일이 없습니다.

## 14장. 부록

### 14.1 용어 사전

| 용어 | 쉬운 설명 |
|---|---|
| **프로젝트** | 자동화 업무 하나를 담는 폴더 |
| **워크플로** | 자동화 업무의 내용 자체 (단계들의 모음) |
| **단계 / 스텝** | 클릭 한 번, 입력 한 번 같은 개별 동작 |
| **리비전** | 업무 내용의 버전 번호. 저장할 때마다 1씩 증가 |
| **사전 검증 / 프리플라이트** | 실행 전에 조작 없이 안전한지 점검하는 것 |
| **대상 / 타깃** | 클릭하거나 입력할 화면 요소 |
| **UIA** | Windows가 제공하는 화면 요소 식별 기능. 좌표보다 정확합니다 |
| **좌표 대체 / fallback** | UIA로 못 찾을 때 위치로 찾는 방식. 조건이 맞을 때만 허용 |
| **체크포인트** | "여기까지 확실히 끝났다"는 표시. 이어서 실행의 기준점 |
| **자격 증명 참조** | 비밀번호 자체가 아니라 **비밀번호의 이름표** |
| **해시** | 파일 내용의 지문. 내용이 바뀌면 완전히 달라짐 |
| **반복 / 이터레이션** | 목록의 각 건을 한 번씩 처리하는 것 |
| **어댑터** | 창 조작·클립보드·표 저장 등 기능 묶음 |

### 14.2 단축키

| 단축키 | 기능 | 언제 |
|---|---|---|
| `Ctrl+Shift+F11` | 일시정지 / 계속 | 기록 중, 실행 중 |
| `Ctrl+Shift+F12` | 종료 / 중지 | 기록 중, 실행 중 |
| `Ctrl+S` | 프로젝트 저장 | Studio 창에서 |

위쪽 두 단축키는 **어느 창에 있든** 동작하며, 자동화 단계에 기록되지 않습니다.

### 14.3 자주 묻는 질문

**Q. 인터넷 연결이 필요한가요?**
아니요. 모든 처리가 내 컴퓨터 안에서 이루어집니다. 인공지능 서버로 데이터가 나가지
않습니다.

**Q. 실행 중에 다른 일을 해도 되나요?**
안 됩니다. 다른 창을 클릭하면 자동화가 멈춥니다. 잘못된 창에 입력이 들어가는 것을 막는
안전장치입니다.

**Q. 컴퓨터를 잠그고 실행해 둘 수 있나요?**
할 수 없습니다. 화면이 잠기면 동작하지 않습니다. 로그인된 상태로 켜 두어야 합니다.

**Q. 정해진 시간에 자동으로 실행되게 할 수 있나요?**
이 버전에서는 지원하지 않습니다. 사람이 직접 **실행** 버튼을 눌러야 합니다.

**Q. 자동화하던 프로그램이 업데이트되면 어떻게 되나요?**
화면이 바뀌면 대상을 못 찾아 실패할 수 있습니다(`target_not_found`). 이때는 업무를
다시 기록하는 것이 가장 확실합니다.

**Q. 결과가 이상한데 상태는 "성공"입니다.**
"성공"은 **정해진 동작을 모두 수행했다**는 뜻이지 **결과가 업무적으로 옳다**는 뜻이
아닙니다. 결과 파일의 **행 수**와 내용을 꼭 직접 확인하세요.

**Q. 실수로 잘못 실행했습니다. 되돌릴 수 있나요?**
이 프로그램은 되돌리기 기능이 없습니다. 그래서 되돌릴 수 없는 업무는 자동화하지
말라고 안내드립니다. 실행 전 **사전 검증**과 연습을 반드시 거치세요.

**Q. 여러 사람이 같은 업무를 쓸 수 있나요?**
네. 프로젝트 폴더를 복사해 주면 됩니다. 다만 각자 자기 컴퓨터의 자격 증명 관리자에
비밀번호를 등록해야 합니다.

**Q. 화면 배율(125%, 150%)을 바꿔도 되나요?**
기록할 때와 실행할 때의 배율이 같아야 합니다. 다르면 실행 전 점검에서 걸러집니다.

### 14.4 한눈에 보는 작업 순서

```
프로젝트 만들기
   │  비어 있는 폴더 선택 → 업무 이름 입력
   ▼
업무 기록하기
   │  창 목록 새로고침 → 대상 창 선택 → 기록 시작
   │  실제 업무 수행 → 기록 종료
   │  단계 이름 고치기 → 검토 내용을 편집기로 가져오기
   ▼
단계 다듬기
   │  이름·값 종류·실패 처리 확인 → 변경 적용
   │  (필요하면 실행 변수 추가 / 반복 만들기 / 대기 조건)
   │  환경 검사 → Ctrl+S 로 저장
   ▼
실행하기
   │  출력 폴더 선택 → 사전 검증 → 실행
   │  (중지: Ctrl+Shift+F12)
   ▼
보고서 확인
      상태 확인 → 행 수 확인 → 필요시 보고서 내보내기
```
